# GraphRail agent workflow

You are the orchestrator; no server-side LLM key or sampling is required. Read the bundled Substreams development, Ethereum, SQL and testing skills. Detailed references are resources at graphrail://skills/references/<filename>.md. Operator hosting work follows the hosted-sink skill; credentials stay with the operator.

1. Call create_pipeline with the user's prompt. Inspect candidate coverage (contracts, ABI events, chain, start block, schema) before reuse. Keyword similarity alone does not prove coverage. Search the official registry with search_substreams_packages before designing a package.
2. This server accepts Ethereum Sepolia only, with Hedera testnet payments through the Blocky testnet facilitator. Reject mainnet requests. Obtain exact addresses, selected ABI event entries, network, startBlock, known active testStartBlock and abiSource from verified sources. Ask for missing scope instead of inventing an ABI. The server does not fetch or execute abiSource.
3. Call create_pipeline with prompt and definition. Supported fields are scalar ABI address, bool, string, bytes/bytes1..32 and int/uint widths 8..256. Each event gets its own typed protobuf and PostgreSQL table. Arrays, tuples, anonymous/overloaded events, indexed dynamic values, aggregates/stores and enrichment are not supported. Do not silently substitute event indexing for those intents.
4. Show the exact schema, coverage, commissioning fee and per-query fee. ABI fields are arg_<snake_name>, amounts are raw exact decimal units. 100000000 tinybar is 1 HBAR. Proceed within the user's spending authorization; keep requestId stable for retries of one purchase.
5. Call commission_pipeline. A payment-enabled MCP client signs locally and retries with official x402 metadata. The server never receives a private key. Ordinary MCP clients need a wallet helper for paid calls. A settled response returns immediately with pipelineId/jobId; builds continue independently.
6. Poll get_pipeline_status every 5–15 seconds. The worker generates Rust/protobuf/substreams.yaml/schema.sql, compiles/tests, packs, validates live db_out JSONL, publishes the package and uses a prepared hosted PostgreSQL slot. It registers only healthy indexing with actual rows in Supabase. Failures retain the receipt; do not buy another commission blindly.
7. Other agents call list_pipelines for free and query_pipeline for paid bounded GraphQL reads. Entity roots support singular(id) and plural(first<=100,skip<=5000,where). where supports equality and blockNumber_gte/lte. Big integers are strings. Example: { transfers(first:5) { id blockNumber arg_value } }. No arbitrary SQL or GraphQL mutations, aggregates, fragments or introspection. Indexed data is persisted in Supabase; query responses are not cached.
8. Retrieve settlement/HCS via get_payment_receipt. For ambiguous settlement retry the SAME signed request, not a fresh payment. A delivered query payment cannot be reused; a lost final response needs operator handling.

Deployment target is StreamingFast hosted SQL into Supabase. db_out emits DatabaseChanges using the official crate; Graph Node v0.42 removed Substreams support, so this workflow does not deploy a Studio subgraph. The public MCP monetizes access to the operator's private indexed dataset and payment/audit service. Seller revenue goes to HEDERA_PAY_TO; creator splitting is not implemented.
